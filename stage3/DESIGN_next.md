## 전제 (C 결과에서)
- 부피 NEO(t4096, 합성 형상군 7개로 학습)는 실제 형상에서 **원시 기저가 약 10배 나빠짐**.
  - span loss 중앙값 1.2e-2, 고유값 오차 9%. cow 73%, dragon 41%.
- 그래도 **역반복 다듬기 1–2회로 회복**되고, 탄성 (c) 기저는 실제 형상 156/156 경우 합격.
- 다듬기에는 형상마다 희소 LU 1회와 블록 풀이 1–2회가 필요함 (스칼라 수 초, 탄성 약 1–4분).
- **"다듬기 없이 원시 NEO만으로" 충분한 기저를 주면 파이프라인이 빨라짐.** 이것이 1번의 목적임.

## 1. 빠른 버전: 다양한 형상으로 재학습한 NEO

### 1-1. 스칼라 NEO 재학습 (Thingi10K 대규모)

**데이터**
- **Thingi10K 형상 풀:**
  - C에서 쓴 엄격 기준(닫힘·다양체·자기교차 없음·연결 성분 1개, 면 2k–200k, CC 라이선스)은 1,750개.
  - fTetWild는 열린 면이나 비다양체도 부피화하므로 기준을 "fTetWild 성공 + 부피 > 0 + 연결 성분 1개"로 완화하면 수천 개로 늘어남 [추측].
  - **테스트와 겹치지 않게:** C의 Thingi10K 10개(file_id 목록, `real_shapes/raw/thingi10k/selected.csv`)와 같은 Thing ID를 가진 모든 파일을 제외함. Stanford 모델(Bunny, Armadillo, Dragon)과 cow는 Thingi10K에 없어서 자연히 분리됨.
- **규모 제안:**
  - Thingi 3,000개 + 기존 합성 4,200개(data_neo2)를 섞음.
  - 형상당 샘플 4개 (quasi 2 + random 2), N = 4096, 목표 96모드 (A1 결정과 같음).
- **정제:** 부피화 후 C와 같은 면 연결 정리(`c_cleanup`)를 적용함. 벽이 점 간격보다 얇은 형상은 자동 제외함 (thingi135364 사례).
- **점 수 분포:** C에서 N = 16384가 8192보다 약간 나빴음. 학습에 N ∈ {4096, 8192}를 섞는 안을 비교군으로 둠.

**비용 추정**

| 항목 | 계산 | 추정 |
|---|---|---|
| HuggingFace에서 npz 개별 다운로드 | 파일당 0.01–1 MB | 3,000개 약 1–2 GB, 수십 분 |
| fTetWild 부피화 | C 실측 23–257초 (중앙값 약 70초, 4스레드) | 6프로세스 × 4스레드로 약 10시간 (CPU) |
| 샘플링 + Delaunay + 목표 96모드 (N = 4096) | 샘플당 약 2초 | 12,000샘플, 16프로세스 약 30분 |
| 디스크 | 4096 × 96 × 4 B ≈ 1.6 MB/샘플 | fp32 약 20 GB, **fp16 약 10 GB** (현재 여유 약 60 GB) |
| 학습 | t4096에서 미세조정, 8시간 상한 | GPU 1–2장 × 8시간 (A처럼 두 설정 비교 가능) |

**평가**
- C의 실제 형상 13개와 기존 합성 테스트셋에서 **다듬기 없이** span loss와 고유값 오차를 봄.
- 기준: 원시 기저 span loss ≤ 1e-3 (현재 1.2e-2).
- 기존 합성 테스트에서 성능이 떨어지는지도 확인함 (망각 여부).

### 1-2. (필요하면) 탄성 저에너지 공간을 직접 예측하는 미세조정
- **하는 조건:** 1-1 후에도 탄성 (c)에 역반복이 필요할 때만.
- **출력:** 3C 채널.
- **목표:** ANP 탄성 연산자의 저에너지 고유벡터 (강체 6 + 96).
  - ν ∈ {0.3, 0.49}를 입력 특징으로 주거나 따로 학습함.
- **데이터 비용:**
  - 탄성 고유분해 (N = 4096, 12.3k 자유도, k = 102): 약 30–60초/샘플 [추측].
  - 12,000샘플이면 16프로세스로 약 6–12시간.
  - 디스크는 fp16 약 15 GB. 스칼라 데이터와 동시에 두지 않도록 순서를 조정해야 함.
- **위험:**
  - 벡터 목표는 좌표 회전과 함께 돌려야 함. g2pt의 회전 증강 수정이 필요함.
  - ν 의존성이 있음.
- **학습:** GPU 1장 × 8시간.

## 2. 극단적 형상 이동 실험 (합성 덩어리형 → 실제·가는 형상)

**목적:** 학습 형상과 전혀 다른 형상에서 구조 주입(우리 방법)이 데이터 효율과 일반화 면에서 Point-DeepONet보다 나은지 보임.

### 2-1. 과제 (결정 필요, ★ 권장)

| 과제 | 입력 → 출력 | 숨은 규칙 (학습 대상) | Point-DeepONet 적합성 |
|---|---|---|---|
| **T1 ★ 탄성 정적 응답** | 형상 + 하중(방향 3성분, 크기) → 변위 3성분 + von Mises | 재료가 깊이에 따라 다른 **미지의 공통 법칙** E(x) = f(표면까지 거리) (예: 표면층이 단단함) | **높음.** 저자 설정(전역 하중 조건 + PointNet 형상 → 변위·응력 4성분)과 형식이 같아 데이터 로더만 바꾸면 됨 |
| T2 열확산 | 형상 + 초기조건 필드 → u(τ) | 미지의 전도도 법칙 κ(깊이) | 초기조건이 점별 필드라 PointNet 입력 채널 추가가 필요함 ("로더만 수정" 조건을 벗어남) |

- T1에서 법칙 f를 모르므로 두 방법 모두 데이터로 배워야 함. 재료가 균질이면 우리 방법은 학습 없이 풀려서 비교가 의미 없음.
- **우리 방법 (T1):**
  - 기저 = (c) (NEO + 회전형 장 + 역반복 + 정적 보정).
  - 계수 네트워크 f_θ(깊이, 좌표 특징) → E(x) → Â = Yᵀ K(E) Y → 변위.
  - von Mises는 변위에서 계산함.
  - 학습 손실은 변위 데이터 오차 (B-2와 같은 구조).
- **Point-DeepONet:** pdon 환경, 저자 기본 설정(40,000스텝, 배치 16, lr 1e-3, 은닉 100).
  - 수정은 데이터 로더뿐임: 우리 npz를 저자 형식 `a`/`b`/`c`로 쓰고, 출력 클리핑과 하드코딩된 평가 경로를 끔.
  - 입력 매핑: x, y, z, d = SDF, m = 형상 부피, l = 하중 크기, c = 하중 방향.

### 2-2. 데이터와 분할
- **학습:** 합성 덩어리형 형상(sh_ball, superquadric)에서 N ∈ {10, 25, 50, 100, 200, 500}개 사례 (형상 × 하중 조합), 시드 {0, 7, 17, 23, 42}.
- **테스트 4종:**
  - 같은 형상군 (합성 덩어리형, 새 형상)
  - 가는 합성 형상 (c_tube, elongated, cup, torus)
  - 실제 형상 13개 (C)
  - 불규칙(random) 샘플
- **정답:** ANP 전체 차수 풀이 (AMG-CG, N = 8192). 사례당 약 10–20초.

### 2-3. 비교군 (D 계획과 통일)
- RAW(정규화·튜닝한 일반 DeepONet)
- STRUCT(우리)
- RAND(같은 폭의 무작위 기저)
- POD(학습 잔차 POD 기저)
- Point-DeepONet
- 매개변수 수를 맞춤 (Point-DeepONet은 은닉 100에서 약 25만 개가 기준).

### 2-4. 비용 추정

| 항목 | 계산 | 추정 |
|---|---|---|
| 정답 생성 | 학습 최대 500 + 테스트 약 400사례, 사례당 약 15초 AMG | 12프로세스로 약 20분 (CPU) |
| 기저 (c) 준비 | 형상당 약 3–7분 (역반복 포함) | 형상 약 150개, 12프로세스로 약 1시간 (CPU) |
| 우리 방법 학습 | 스텝당 수십 ms, 수천 스텝 | 실행 1개 10–30분; 6 N × 5 시드 = 30개 → GPU 3장에 약 2–5시간 |
| Point-DeepONet 학습 | 40,000스텝, N_pt = 8192, 배치 16. 3090에서 스텝당 약 50 ms [추측] | 실행 1개 약 35분; 30개 → GPU 3장에 약 6시간 |
| RAW / RAND / POD | 우리 방법과 비슷 | 합계 약 6–10시간 (GPU 3장) |
| 디스크 | 사례당 8192 × (입력 9 + 출력 4) × 4 B ≈ 0.4 MB | 수백 MB |

- 합계: CPU 약 1.5시간 + GPU 약 12–20시간 (3장 병렬 시 실제 시간 약 5–7시간).
