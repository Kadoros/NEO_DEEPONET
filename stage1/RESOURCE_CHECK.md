## 3. 변경 사항

1. **조기 중단 규칙** (미리 정한 규칙):
   - 30k step에서의 best 검증 오차가 같은 p의 실행들이 30k에서 낸 최솟값의 **1.2배를 넘으면** 중단함.
   - 이미 30k를 지난 실행도, 나중에 더 좋은 기준값이 생기면 같은 규칙으로 중단함.
   - **run 0 (p=64, lr=3e-4)을 중단함:** val@30k 0.1645 > 1.2 × 0.1255(run 1). 중단 시점은 약 45k step이었음. 부분 학습 곡선은 로그에 보존하고, `meta_run0_earlystop.json`에 기록함.
2. **체크포인트 가능한 큐 워커로 재배치** (`train_don_fair.py --worker`, `don_orchestrate.py`):
   - 아직 시작하지 않은 실행(3–9)은 워커가 claim 파일로 하나씩 가져감.
   - 10k step마다 체크포인트(모델, optimizer, scheduler, numpy/torch RNG 상태, best, stale)를 저장하고, 중단되면 그 지점에서 이어서 재개함.
   - 순서: 4, 5, 7, 8, 9, 3, 6. 유망한 학습률을 먼저 돌려 조기 중단 기준값이 일찍 생기게 함.
   - **학습 중인 run 1과 run 2는 재시작하지 않음.** 끝나는 즉시 원래 큐 프로세스를 멈추고(다음 대기 실행이 몇 초 진행된 상태일 수 있음), 워커가 그 GPU를 이어받음.
   - GPU 0에서는 13:54에 워커가 run 4를 시작함.
3. **P0 평가:** 오케스트레이터가 `data_p0/index.csv` 생성을 감지하면 GPU 0에서 `p0_eval.py`를 시작함(DON 실행과 공유). 평가는 약 15분이고, 그동안 GPU 0의 DON 속도는 절반 정도로 떨어짐.

**바꾸지 않은 것과 이유:**
- GPU당 실행 수: 실측상 이득이 없음.
- P0 프로세스 수(16): 재시작 손실이 이득보다 크고, CPU 한도 안에 있음.
- 실행 중인 run 1·2: 규칙상 재시작 금지. 체크포인트가 없는 기존 프로세스이므로 끝까지 둠.

## 5. 재현성 영향

- **SIGSTOP 일시정지:** 계산 순서와 난수에 영향 없음.
- **조기 중단:** 어떤 실행을 끊을지가 30k 시점에 이미 존재하던 기준값에 의존하므로 **실행 순서에 따라 결정이 달라질 수 있음**. 중단된 실행은 최종 선택 후보에서 빠짐. 결정 근거(값과 기준)는 `results_don_fair/state/`와 `logs/orchestrate.log`에 기록됨.
- **체크포인트 재개:** RNG와 optimizer 상태를 복원하므로 원칙적으로 같은 궤적임. 다만 PyTorch CUDA 커널 일부(예: 역전파의 atomic 누적)는 비결정적이라, 재개나 동시 실행(P0 평가와 GPU 공유)이 있으면 **마지막 자리가 미세하게 달라질 수 있음**. 1단계 학습도 결정적 모드를 켜지 않았으므로 같은 수준의 비결정성이 원래부터 있었음.
- **P0 평가:** 추론만 하므로 공유 실행이어도 결과는 같음(부동소수점 수준 차이 제외).
- **기존 결과(1단계, results_eps):** 건드리지 않음.
